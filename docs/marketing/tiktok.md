## 1. 方針

### 基準の1行(全部の投稿をこれで通す)

> **見た人が、うっかり流れていく自分の毎日を思い出すか。**

伸びそうでも、これに当てはまらないものは出さない。アカウントの客層がずれると、後の投稿が習慣に興味のない人に配られる(通説【未確認】)。

### 見てほしい人(仮)

20〜30代。朝や夜に「やろうと決めたこと」がある。意志が弱いとは思っていないが、気づくと時間が過ぎている。iPhone を使っている。

### 説明の軸

「忘れている自分を、いまに戻す一声。」/ `The voice that brings you back.`(spec §1)。「弱い自分に打ち勝つ」「叱咤激励」「自分を追い込む」とは言わない(spec §9-14)。言葉の厳しさは本人の自由(spec §9-7)。

### お手本を実際に見て分かったこと(2026-11-15 夜。本人の Chrome で `@strongermobile` の一覧と7本を確認)

**⚠ 下の表とストック P01〜P07 は、これを見る前に作ったもので外している。**P01〜P07 は使わない(写真が無い・セリフでない・2枚目にオチが無い・説明的)。

- **型は「ひと言 → アプリの画面がオチ」の2枚。**1枚目の文は2種類だけ: 人に言われるセリフ(かぎかっこ付き。`"bro you've changed"`)か、芝居がかった言いかけ(`I went from zero...`)
- **2枚目はアプリの「証拠」の画面に、1〜3語のひと言**(`I know.` / `yeah.` / `also bro:`)。説明はしない
- 一番伸びた投稿(120万再生)は、2枚目の運動履歴のマス目が文字になっていた。**画面そのものが驚きや笑いのある絵**
- 写真は雑でよい(お手本は自分の足元を真上から)。文字は TikTok の標準の白い字に黒い縁
- **同じ1枚目の文を何十回も使い回す。**同じ文でも再生は9千〜120万。ほとんどは数千で、当たりはたまに。数を出して待つ
- 説明文は2〜4語、ハッシュタグ3つ、音楽つき

**KATSU での形(本人と決めた):**
- 型は借りるが、文と画面は自前(相手の文の直訳はしない。「変わった?→66日」「0日から…66日」は近すぎるので外した)
- **1枚目の写真は「待っている物」**(使われないままの靴・閉じたノート・積んだ本・伏せたスマホ)。足元の写真は使わない。時計が写る写真も混ぜる
- 柱は「**言い訳する今の自分を、昨日の自分の言葉が暴く**」(KATSU でしか作れないオチ)
- 文の案: 「"明日から本気出す"」→「昨日の自分:」+ 通知 /「"最近、朝早いね"」→「まあね。」+ 今日の画面(66日のうち23日)/「"今日も走るの?"」→「23日目。」/「"どうせ続かないでしょ"」→「33日目。」
- 通知の言葉は「やるって決めたのは、お前だろう。」で統一(オチの決まり文句)。ルーティン名だけ場面に合わせる
- ~~TikTok は日本語と英語の2アカウント~~ → **英語の `@katsuhabit` 1つで始める(2026-11-16、本人判断)。**時間を1か所に集めるため。5本出したら「視聴者の国」を見る。日本ばかりなら日本語用を作るか、YouTube Shorts へ。投稿は同じ写真から日本語版も作っておく
- 【未確定】「三日坊主」を、人に言われるセリフとして使うか(本人が決める)

### 1本目の失敗から決め直したこと(2026-11-16 夜)

- **1本目(ノートの写真 → ロック画面の通知)は伝わらなかった。**通知の文字が小さく、「自分で書いた言葉が、サボると届く」という仕組みがどこにも見えなかった。お手本の「形」だけをまね、「読まなくても一目で分かる絵」という中身を落としていた。「自分のみ」に変更済み
- **1本で伝えることは1つ:** 「よくある『時間です』の通知と違い、やる気のあった日の自分が書いた言葉が、サボったときに届く」
- **見せ方:** 言葉そのものを画面の主役にする。通知は実物の見た目に合わせて HTML で大きく描き直す(`~/katsu-video/mock/`、`base.css`)。比較(よくある通知 vs 自分の言葉)か、仕組み(書く → サボると届く)の2枚
- **出す前に、KATSU を知らない人がスマホで2秒見て分かるかを、本人に見てもらう**
- **プロフィールにリンクを置けるのは、フォロワー1,000人を超えてから**(2026-11-17、本人が TikTok の条件で確認)。自己紹介には URL を文字として書ける(押せるリンクにはならない)。⚠ プロフィールの変更は反映まで数時間かかることがある(11/16 に「はじかれた」と誤って判断した。翌日には反映されていた)。それまでは自己紹介で「search "KATSU habit"」と伝える。ビジネスアカウントへの切り替えは手間に見合わないのでやめた。LP は App Store のマーケティング URL などで使う

### AI の映像を使うときの4つ

1. 基準の1行を通る
2. **静か:** 壊れる・消える・驚かせる映像にしない。炭の色合いで、ゆっくり見せる。「○○が世界から消えたら」の型は使わない(見に来る人が違う)
3. **言葉は人が書く:** 画面の文と、ロック画面に届く言葉は本人が書いたものだけ
4. 「AI 生成」のラベルを付ける

候補: 朝の枕元に「昨日の自分」が静かに立っている / 時計の針だけが進み、部屋の光が朝から夜に変わる / 墨で描いたような1日の時刻表。

## 3. 作り方

素材と仕上がりは**リポジトリの外の `~/katsu-video/`**(リポジトリは公開なので、本人の言葉が写った素材を入れない)。

```
~/katsu-video/
  raw/slides/   2枚目の画面(シミュレーターのスクショ、ストアのスクショの切り抜き)
  cuts/         台本(P01-ja.cut など)
  out/          仕上がり(Pxx-ja/ に 1.png・2.png・mp4)と 投稿メモ.md(説明文・タグ)
```

**2枚目の画面を撮る(シミュレーター):** `bash tools/sim/build.sh` で撮影用の版を入れてから

```sh
xcrun simctl launch <UDID> com.kisshi.gradhabit -katsuDevSeed progress -katsuDevTheme morning -AppleLanguages "(ja)" -AppleLocale ja_JP
xcrun simctl io <UDID> screenshot ~/katsu-video/raw/slides/today.png    # 起動から20秒ほど待つ
```

- 状態・画面・ルーティンの組の名前は `docs/HANDOFF.md`「撮影用の状態と画面」
- ⚠ 入れ直した直後は通知が許可されておらず、Today に「通知がオフなので」の箱が出る。一度アプリの中で「オンにする」→「許可」を押す
- ロックは `osascript -e 'tell application "Simulator" to activate' -e 'tell application "System Events" to keystroke "l" using command down'` で送れる(⚠ 再起動の直後は効かないことがあった)
- 動画の素材は `bash tools/video/record.sh`

**組み立てる:**

```
# ~/katsu-video/cuts/P06-ja.cut
card  3  もし、決めた日の\n自分が\n話しかけてきたら。
image ../raw/slides/lock-zoom.png 3
```

```sh
python3 tools/video/cut.py ~/katsu-video/cuts/P06-ja.cut -o ~/katsu-video/out/P06-ja/P06-ja.mp4 --stills
```

- `--stills` で場面ごとの PNG(写真モードの1枚目・2枚目)も出る
- `card` の文字は1行10字まで(それ以上は語の途中で折り返す)。`\n` で区切る
- 2枚目の文字が小さいときは、画面を切り抜いて大きくする(ロック画面は通知のまわりだけ)
- ⚠ **見せたいもの(通知・日数・チェック)は、TikTok の画面で隠れる場所に置かない**(2026-11-16、1本目で通知が説明文と重なって読めなかった)。1080×1920 で、上 200px(タブ)・下 450px(名前・説明文・曲名)・右 150px の高さ 700〜1600px(いいね等のボタン)を避ける。ロック画面は通知のまわりを切り抜いて真ん中に置く。アプリの画面は幅 860px に縮めて左右に余白を取る(`scale=860:-1,pad=1080:ih:110:0`)。確かめるときは、この範囲を赤く塗って重ねる
- 1枚目を写真にするときは、写真に TikTok の文字の機能で文を入れる(TikTok でいつも見る字のほうが広告に見えない)
- 音楽は投稿のときに TikTok で付ける(商用利用可の音源、落ち着いた曲)

**アニメーションを作る(2026-11-19):** 絵で人を動かす動画は `tools/video/anim/`。HTML の canvas で `?t=秒` の1コマを描き、`render.sh` で全部のコマを描いて mp4 にする(例: `happy.html`「a 2-minute habit, day 1 → day 66」18秒。描くのに10分ほど)

```sh
bash tools/video/anim/render.sh tools/video/anim/happy.html 18 ~/katsu-video/out3/happy.mp4
```

**スマホから頼む:** Mac の Claude Code で `/remote-control`(Mac は起こしておく)。クラウドの Claude Code では Mac の素材とシミュレーターが使えないので、文面を考えるだけになる。
