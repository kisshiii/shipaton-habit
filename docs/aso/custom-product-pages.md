## 0. ねらいと前提

- **解く問題:** 検索で表示 → ページを開く が約5%(弱い)。ページ → ダウンロード は約64%(強い)。**開いてもらえれば入れてもらえる。**検索結果に並ぶ最初の3枚とプロモーションテキストを、探している言葉に合わせる
- **CPP にキーワードを割り当てると、その語の検索結果に CPP の見た目で出る**(最大70ページ)。割り当てる語は**アプリ本体のキーワード欄に入っている必要がある**。1つの語(組み合わせ)は1ページにだけ割り当てる
- 各ページは **3枚**のスクショで組む。検索結果の縦長表示で見えるのは最初の3枚なので、そこで勝負する(4枚目以降はメインのページと同じものを続けてよい)
- ディープリンク: **不要**(全ページ、アプリの通常起動でよい)
- 守ること(`asc-listing.md` と CLAUDE.md の決まり): 「失敗」「サボった」「連続」「in a row」「streak broken」「missed」を使わない / 罪悪感をあおらない / 感嘆符なし / `research found` と言わない(66日は1本の研究の中央値)/ アプリが言葉を用意しているように見せない / `三日坊主` `夜更かし` のような人に貼るラベルはキーワード欄にだけ置き、見える文面に出さない

### 【未確認】(ASC の画面で確かめること)

- 名前・サブタイトルに入っている語(habit / tracker / routine / reminders / 習慣化 / ルーティン など)を CPP に割り当てられるか。この下書きでは**キーワード欄の語だけを割り当てる**前提で組んだ
- キーワードの割り当てがロケールごとか(この下書きは en-US と ja を別々に割り当てる前提)
- 1ページに割り当てられる語の数の上限
- CPP のプロモーションテキストを審査なしで差し替えられるか(本体ページは審査なしで変えられる)
- 日本語のキーワード欄が分かち書きされるか(例: `モーニングルーティン` と名前の `ルーティン` がどう組み合わさるか)
- 検索語の人気度。広告は使わない方針(plan §9)なので Search Ads の数値は見られない。下の「狙う検索語」は人が実際に打ちそうな語の推測で、ボリュームは測っていない

## 1. キーワード欄(本体)の差し替え案

CPP に割り当てる語を先に本体のキーワード欄へ入れる。**1.0.3 の公開と同時に差し替える**(キーワード欄はバージョンと一緒に審査に出る)。

### 英語(en-US)

**今:**

```
streak,discipline,motivation,accountability,morning,daily,goal,promise,checklist,productivity,gym
```

(97文字)

**案:**

```
morning,wake,workout,gym,sleep,bedtime,study,phone,screen,detox,resolution,new,year,goal,motivation
```

(**99文字** / 上限100)

| 残した | 足した | 外した |
|---|---|---|
| morning, gym, goal, motivation | wake, workout, sleep, bedtime, study, phone, screen, detox, resolution, new, year | streak, discipline, accountability, daily, promise, checklist, productivity |

**外した理由:**

- `streak` ── 説明文で「連続記録で縛らない」と言っている。連続記録のアプリを探す人を呼び、開いた先で話が食い違う。CPP の文面にも使えない語
- `checklist` `productivity` ── ToDo・タスク管理を探す人の語。KATSU は ToDo ではない(spec §1)
- `accountability`(14文字)── 長いわりに「誰かに見張ってもらう」系(相手のいるアプリ)を呼ぶ。KATSU に相手はいない
- `discipline`(10文字)── 意図ごとの語に枠を回すため。残したい場合は `screen` と `new` を外すと入る(下の注意を読んでから)
- `daily` `promise` ── 単独で検索されることが少ないと見て外した【未確認】
- 名前の `Habit` `Tracker` `Routine`、サブタイトルの `Reminders` `own` `words` は Apple が別に索引するので入れない(今までどおり)

⚠ 外した語で今どれだけ表示されているかは ASC で語ごとに見られない【未確認】。差し替え後2〜3週間、本体ページの表示回数が落ちていないかを見る。

## 3. ページごとの中身

### 共通: スクショの作り方

- 組み方は今と同じ(`tools/compose-screenshot.swift`、1290×2796、暗い背景に2行のキャプション)。キャプションは HelveticaNeue 118pt で幅1210px なので、**英語は1行おおむね19文字まで、日本語は全角10文字まで**を目安にした(実際に組んで確かめる【未確認】)
- **⚠ Today・節目・卒業の画面は、意図に合ったルーティンで撮るには撮影用の状態を足す必要がある。**今の撮影用データ(`src/dev/demo-seed.ts`)はルーティンが「ランニング / 英語15分 / 日記」に固定。アプリの中で名前を書き換えると**数え直しになって Day 1 に戻る**ので、撮影後に直す手は使えない。意図ごとのルーティンを持つ撮影用データを足すのは別の作業(このドキュメントでは決めない)
- オンボーディングの段は、本物の流れでそのまま撮れる(「何を変えたいか」で選ぶと、次の段に例が入る)
- ロック画面の通知は、撮影用に書いた言葉を本物の流れで届けて撮る(オンボーディングの「試しに届ける」、またはルーティンを1分後に置く)。**`asc-listing.md` の決まりどおり、ここで見せる言葉だけは本気で書く。**下の例は、やらなかった行動に向けた言葉で、人を否定しない(ソフトガードに引っかからない形)。60文字以内
- 時刻の表記はアプリに合わせて24時間制

1. **F. 新年の目標(英日)** ── 時期が決まっていて、待てない。12月〜1月は「新年の抱負」で探す人が一年で一番多く、1.0.3 の「1月1日から始める」、App 内イベント「1月1日から、66日」、フィーチャーの推薦と全部が同じ方向を向く。CPP も審査があるので、**1.0.3 の公開と同時に出しておく**。1月に入ったらプロモーションと1枚目を差し替える
2. **A. 朝のルーティン(英日)** ── 年中検索される語で、名前の `Routine` と `morning` がそのまま `morning routine` になる。日本語の `朝活` `早起き` `モーニングルーティン` は**今のキーワード欄にすでに入っていて、今も見つかっている語**なので、検索結果に出る見た目を替えるだけで効く。オンボーディングの1つ目の選択肢と同じ例(06:30 水を一杯)なので、ページと開いた後の体験がずれない

- **E は最後。**意図のずれ(ブロッカーを探す人)が一番大きく、ページを開いた人の64%を下げるおそれがある。A と F の数字(CPP ごとの表示 → 開く率)を見て、5%からどれだけ動いたかを確かめてから出す
